# plan_0011 - 리모트 DB 덤프 기반 서비스별 DB 분리/이관 및 단일 SQL 마이그레이션

## User Requirements

- 리모트 DB를 덤프한 뒤 서비스별 DB로 분리하고 데이터를 이관해야 함.
- 이관 검증이 가능한 테스트 베이스가 필요함.
- DB 마이그레이션은 단 하나의 SQL 파일로 관리하고 싶음.

## Goal

- 리모트 단일 DB(모놀리식)를 로컬 다중 서비스 DB 구조로 재현 가능한 방식으로 분해/이관한다.
- 이관 절차를 `single-entry SQL` + 자동 검증 스크립트 조합으로 표준화한다.
- 각 서비스 DB마다 전용 유저와 테이블 가시성을 확보한다.
- 단, `rule-engine`/`BE-router`는 기존 `gtrpgm` DB + `gtrpgm` 계정을 유지한다.

## Scope

- In:
  - 리모트 덤프 절차 문서화 (`pg_dump`, 스키마/데이터 분리)
  - 단일 SQL 파일 생성: `db/migrations/0001_monolith_to_service_split.sql`
  - 이관 검증 스크립트/테스트 베이스 구축 (`scripts/integration_*`, `api_verification.py` 확장)
- Out:
  - 프로덕션 DB 직접 변경 자동화
  - 온라인 무중단 마이그레이션

## Implementation Plan

- Step 1: 서비스 코드 기준 테이블 인벤토리 확정 (`docs/db_table_inventory_by_service.md`).
- Step 2: 서비스별 타깃 스키마(state-manager, scenario-service, gm, rule-engine) 매핑 테이블 정의.
- Step 3: `0001_monolith_to_service_split.sql`에 DDL/DML 순서를 단일 엔트리로 작성.
- Step 4: 샘플 데이터 이관 후 row count/hash/핵심 관계(Cypher 포함) 검증.
- Step 5: 테스터에서 `STATE_MANAGER_BASE_URL`과 remote BE-router 경유 검증을 같은 데이터셋으로 실행.

## Unit Test Plan (must)

- What to test:
  - 이관 대상 매핑 함수/쿼리 정합성
  - 누락/중복 데이터 탐지 로직
- Command:
  - `uv run pytest tests/test_repository_sql.py tests/test_logic_integration.py`

## E2E Plan (must)

- How to run:
  - `uv run python scripts/verify_sql_syntax.py`
  - `uv run python scripts/api_verification.py`
  - `uv run python scripts/integration_commit_flow.py`
  - `uv run python scripts/integration_state_guards.py`
- Validation:
  - 단일 SQL 적용 후 모든 통합 스크립트 PASS.
  - 세션/턴/관계/인벤토리 핵심 경로에서 이관 전후 의미적 동등성 확보.

## Local Validation Gate (approval-first)

- 원칙:
  - 리모트 적용 전, 로컬에서만 dump/restore/migration 검증 완료.
  - 검증 결과를 사용자 확인 후에만 다음 단계(원격 적용 준비) 진행.
- Local run order:
  - `pg_dump`로 로컬 기준 백업 생성 (schema/data 분리).
  - 루트 `docker-compose.local.yml`의 `db-migrator` 또는 수동 `psql`로 `db/migrations/0001_monolith_to_service_split.sql` 적용.
  - row count + 핵심 API/통합 테스트 실행.
  - 실패 시 롤백 후 SQL 수정.
- Rollback:
  - 트랜잭션 실패 시 자동 롤백을 기본으로 하고, 별도 복구는 백업 dump로 재적재.
